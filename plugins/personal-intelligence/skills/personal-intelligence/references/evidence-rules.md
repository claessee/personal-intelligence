# Evidence and routing rules

Read the configured `profile.json` at the location supplied by the user/workspace. Source entries give logical IDs, domains, subjects, roles, kind, integration and logical location/instruction references. Routes match one domain/intent/subject and require named qualifiers. The private `local-map.json` resolves only selected local source IDs and their existing instruction paths. `requirements.json` preserves independent confirmed setup input; ordinary questions rarely need a full requirement audit.

## Authority is specific to the claim

Use live authoritative → canonical maintained → original → working/derived → memory within the same fact/subject/period. Source registration, filename, modification time, installed app or queued message cannot establish current authority, approval, runtime state or delivery.

- Health: choose one patient. Maintained summaries supply context; a newer explicit clinical original supersedes only the affected older field for that patient. Compare clinical examination/report dates, not file dates. Do not infer medication changes or count identical aliases as independent reports.
- Organization/property: action registers track recorded work, decision indexes point to evidence, and approved/signed originals control formal decisions only for the approving body's scope. Later correspondence can change operational state without establishing assembly approval. Keep organization and owner-private permissions separate.
- Travel: plans establish intent; supplier confirmations establish booked terms. A relevant confirmation can be old mail for a future stay. Accommodation includes resorts, apartments, timeshares and other stays; discover using actual property/provider/date clues. Later supplier changes may update status. A label's coverage is only what the user/evidence explicitly establishes.
- Finance: retrieval requires an explicit financial question and bounded account/topic/date scope. A deliberately requested aggregate-account scope is valid; do not insist on one account for an all-account question. A recorded ledger balance differs from an opening-plus-transactions calculation or provisional/unreconciled result. A definitive balance requires verified semantics/status for the selected account. Schedules can be stored definitions without expanded recurrence or unpaid status; expose that exact capability limit. No bank operations or raw-database fallback.
- Personal/professional facts: use designated canonical facts/provenance and requested fields; unknown stays unknown. Third-party contact details and current appointments/reminders need their live services. Preserve a discrepancy instead of silently preferring incidental contact data.
- Home/technology: manuals and runbooks establish documentation; source code establishes implementation intent. Deployment, runtime and current device state need their own evidence.

## Privacy and safe discovery

Require the patient or private-owner choice before reading mixed containers. Finance is excluded from background/general discovery; a document mentioning an account cannot authorize a financial query. Identity fields require a task-specific need. Secrets, credentials, recovery material, authentication state and unrelated records remain excluded before extraction/output. Preserve existing domain instructions rather than concatenating them into a new universal policy.

Gmail label workflows start with the exact configured label plus topic/item clues. Respect pagination and searched coverage; read originals before negative claims. A later-change lookup may be narrowly expanded within the same task, with its purpose stated. Do not treat arbitrary unlabeled arrivals as a reason to scan the mailbox. Sender/email received date differs from event or clinical date. SENT delivery is established by the actual matching provider SENT record, not a label, draft or queued transmission.

If an existing tool cannot perform the requested scoped read, report that operation and its limitation. Do not invent an unavailable connector, activate a synthetic adapter, ask for a discoverable identifier before lookup or substitute an automatic generic answer. Provider configuration, readiness and live execution are distinct. Only a registered, permitted, dated fallback can be used, explicitly qualified; this package enables no automatic fallback.

## Answer evidence

Give source/document/provider identity and precise locator where available; relevant fact date/window; retrieval time for live/freshness claims; original/derived/canonical role; approval/body scope where applicable; coverage and actual limitations. Store no body logs. A useful answer does not require reciting every field when irrelevant, but the evidence must make the claim assessable.
